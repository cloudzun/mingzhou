## 0-1 gstack 是什么

**仓库：** https://github.com/garrytan/gstack （MIT 许可，作者 Garry Tan / YC；以 Claude Code 为主，其他编码智能体为实验性支持）

**一句话：** gstack 是 Garry Tan 开源的 AI 开发工作流框架，它的核心不是代码，是**八环顺序**——先逼问需求（`/office-hours`）、再锁规格（`/spec`）、再会审（`/autoplan`）、然后才允许写代码（第 4 环受控施工）、再审查（`/review`）、实机验收（`/qa`）、发布（`/ship`）、量化复盘（`/retro`）。

**八环一览（本手册只讲这八环）：**

| 环 | 斜杠命令 | 这一环做什么 | 环末交什么 |
|---|---|---|---|
| 1 | `/office-hours` | 把口语需求逼成目标、边界与被否方案 | 讨论记录 + 设计文档雏形 |
| 2 | `/spec` | 把需求钉成可验收规格 | `SPEC.md`（含 NOT in scope） |
| 3 | `/autoplan` | 四视角串行会审（CEO / 设计 / DX / 工程） | 义务清单 + 是否开工的结论 |
| 4 | （无命令） | 照规格受控施工，每步留证据 | 可运行的增量 + 技术债账本 |
| 5 | `/review` | 结构排雷与安全审计 | 缺陷清单 + 修复提交 |
| 6 | `/qa` | 真机走核心闭环与异常路径 | 测试证据 + `UNVERIFIED` 项清单 |
| 7 | `/ship` | 覆盖率审计、文档同步、发版 | PR / 发布记录 |
| 8 | `/retro` | 用 Git 数据量化复盘 | 复盘报告 + 下一轮改进项 |

> **八环是本手册的切分，不是官方原名。** 官方 sprint 是七段：Think → Plan → Build → Review → Test → Ship → Reflect。本手册把 Plan 拆成「锁规格 / 会审」两环（`/spec` + `/autoplan`），其余一一对应，凑成 8 个各自能验收的环节。
>
> **也别把八环当成 gstack 的全部。** 官方技能有几十个（repo 自述「23 opinionated tools」，另有一批可选技能），本手册只挑**能验收的最小闭环**这八环；其余技能按需用，不属于八环闭环。
>
> 八环的流程版（含两道硬门禁）是图 1-2，见第一篇 A-1。

**为什么顺序不能跳：** 跳过第 1–3 环直接写代码，后面每一环都会退化成"给已经写好的东西补文档"。这是我们观察四幕迭代时最想让你看见的一件事——R1 到 R3.5 加了那么多功能，八环的**定义**一次没变，变的只是每环的投入。

| 你可能听过 | 实际情况 |
|---|---|
| "gstack 是个代码生成工具" | 不是。它不生成代码，它约束你和智能体的协作顺序 |
| "装好就自动变强" | 不会。它提供的是技能与门禁，判断仍然由人做 |
| "八个环 = 八个命令" | 只有 7 个环有斜杠命令；**第 4 环"受控施工"没有命令**，是照规格手写加护栏 |

## 0-2 装 gstack：一段提示词

**要点先说：** gstack 不绑定某一种编码智能体。它是一包技能（skills）+ 一套工作流约定，装到哪个宿主里由你定。**推荐做法：把下面这段直接贴给你的编码智能体，让它自己装、自己验、自己报结果**——装环境本来就是它该干的活，你只要会验它说的对不对。

**主推：贴这段提示词**

```text
1. 网络配置：pip 使用清华镜像源，先执行 `pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple`
2. 网络配置：GitHub 访问走代理 `https://ghfast.top`，克隆仓库时 URL 前缀加 `https://ghfast.top/`
3. 克隆 `https://github.com/garrytan/gstack.git` 到用户主目录：
   `git clone --single-branch --depth 1 https://ghfast.top/https://github.com/garrytan/gstack.git ~/gstack`
4. 运行它的 setup 脚本，host 请自行判断安装合适的版本：
   `cd ~/gstack && ./setup --host auto`；缺 bun 先装 bun（需 v1.4.2 以上）再重跑
5. 装完后验证 `/office-hours` `/spec` `/autoplan` `/review` `/qa` `/ship` `/retro` 这些技能：
   先跑 `cd ~/gstack && ./setup --status`，按输出里每一行 install 的 host / tier / path 逐个确认；
   再实际触发一次 `/office-hours`，能开始追问项目背景即为可用。
   不要只认某一个 agent 的专属路径（不同宿主的落点不一样）。
6. 告诉我安装结果：宿主、tier（full / experimental / instruction-only）、技能落点路径、失败项与原因。
```

**为什么让它自己判断 host：** 它能看到你本机装了什么（Claude Code、Codex、OpenCode、Cursor…），`--host auto` 会把检测到的宿主全装上；你手动填反而容易填错标识。

**验证的三条判据（别只看它说"装好了"）：**

1. `./setup --status` 有一行对应你的宿主，且 `tier` 不是 `instruction-only`；
2. 那一行给出的 `path` 目录里，`office-hours`、`spec`、`autoplan`、`review`、`qa`、`ship`、`retro` 七个技能都在；
3. 在宿主会话里触发 `/office-hours`，它开始追问你的项目背景（而不是提示"未知命令"）。

### 可选：手动三条命令（不想贴提示词就看这里）

```bash
git clone --single-branch --depth 1 https://github.com/garrytan/gstack.git ~/gstack
cd ~/gstack && ./setup --host auto        # 只装某一种宿主就 --host claude / codex / opencode …
./setup --status                           # 一行一个 install：host / tier / scope / version / path
```

国内网络拉不动 GitHub 时，克隆 URL 前加 `https://ghfast.top/` 前缀（同提示词第 2 条）。

### 宿主适配：先看你在哪一类

| 类型 | 典型宿主 | 官方 tier | 八环怎么用 |
|---|---|---|---|
| **A 本地 CLI / IDE 智能体** | Claude Code、Codex CLI、OpenCode、Cursor、Copilot CLI、Gemini CLI、Antigravity CLI | Claude Code = **full**（安全闸由钩子强制执行）；其余 = **experimental**（装了能跑，安全闸只是建议） | `./setup --host auto` 或 `--host <名字>`；八环变成斜杠命令（部分宿主是 `gstack-` 前缀，或要"点名技能"） |
| **B 只有"读规则"能力的工具** | Slate，以及能读 `AGENTS.md` 的编辑器 | **instruction-only**（不落地技能目录） | 没有命令可跑：把 gstack 的 `agents-digest` 或对应 `SKILL.md` 贴成项目规则，按流程走 |
| **C 纯对话型网页智能体** | 各类网页聊天 | **无**（官方宿主表里没有这一类） | **不能装、不能跑**；只能"借流程"：把八环当检查清单逐环产出文档，你人工落盘 |

**C 类为什么不能跑（判据三条，缺一条就只能借流程）：**

1. 能执行本地命令（`git clone`、`./setup`、跑测试、开浏览器）；
2. 能读写你的仓库（`/review` 要看真实 diff，`/ship` 要跑测试开 PR）；
3. 能持久化技能目录，让下次会话还加载得到。

网页对话三条全不满足——它没有你的文件系统，也没有你的 shell。所以它对 gstack 的正确用法是**借流程**，不是**跑 gstack**。这两件事在报告里要分开写，别把"我按八环写了文档"写成"我跑了 gstack"。

**C 类借流程写法（不装也能按八环走）：**

```text
按 gstack 八环依次推进，顺序不可跳过、不可打乱：
第 1 环 office-hours → 第 2 环 spec → 第 3 环 autoplan → 第 4 环 受控施工
→ 第 5 环 review → 第 6 环 qa → 第 7 环 ship → 第 8 环 retro。

每一环结束停下汇报：这一环做了什么、交了哪些文件、门禁结果是什么。
需要我拍板的地方，列 2 到 3 个选项和各自代价，等我选。
每环产物（SPEC、义务清单、测试证据、复盘）在对话里给全，我自己贴回仓库。
```

> **本手册的立场：不指定编码智能体型号。** 你用什么工具都行，判据只有一条——**八环的产物有没有落盘**。用了高级工具但产物不落盘，等于没做；用网页版但每环都交了文件，照样算过关。

### 装不上怎么办

| 现象 | 原因 | 处理 |
|---|---|---|
| `git clone` 卡住或 443 超时 | 国内网络 | 用 `ghfast.top` 镜像前缀；或让讲师发离线包 |
| `./setup` 提示不认识的 host | 宿主标识写错 | `./setup --help` 看列表；你的宿主不在表里就走 B/C 类 |
| 装完仍"未知命令" | 技能落到了另一个宿主目录，或宿主没重启 | `./setup --status` 看 path；重启宿主；不对就删掉 `~/gstack` 重装 |
| 技能能触发但不按顺序走 | 缺流程纪律 | 补贴 C 类借流程那段；或加"禁止全自动执行、每环停下汇报"的约束 |
| Windows 下 `./setup` 不可执行 | 没有 bash，或缺 Node.js | 用 **Git Bash 或 WSL**；Windows 上 bun 与 node 必须都在 PATH；也可在 PowerShell 跑 `.\setup.ps1` |
| Windows 报 `Permission denied`（browse 等二进制） | Smart App Control 拦未签名二进制 | 关掉 Smart App Control，或改在 WSL 里跑 |
| `./setup` 说 `/cso` 不可用 | 缺原生工具链（VS Build Tools / PowerShell） | 可选项，不影响八环；需要再补装 |

## 0-3 证据四态：写"验过了"之前先交代有多硬

**一句话：** 这四个词的作用只有一个——**防止"没验的事被写成验过了"**。

| 你实际的情况 | 报告里该写 | 最常见的错法 |
|---|---|---|
| 真跑过、有输出 | 正常写结论 + 附证据文件 | — |
| **只有真人能验**（好不好用、无障碍、真实用户） | `UNVERIFIED`（未验证） | 写成"通过" |
| **想验但工具或端点用不了** | `unavailable`（不可用） | 编一个分数 |
| **只验了一部分** | `partial`（部分覆盖） | 写成"全覆盖" |
| **本地验不了，得部署到远端或别人配合** | `requires-remote`（需远端验证） | 写成"本地已验证" |

**真实例子：** R1 健康分 98、R2 是 94、R3 是 95——**一个都不等于通过**。以 R2 为例：健康分 94，可这个数字不能单独看，它旁边还写着几行：无 Critical/High，2 个 Medium 与 2 个 Low 未修，人工验收只做了一部分，无障碍相关项 `UNVERIFIED`。分数旁边缺这句，就会被读成"通过"。

**铁律：未验证不等于已验证为否。** 工具没报问题，可能只是它没覆盖到——不能写成"没有问题"。

## 0-4 脱敏与密钥纪律

**一句话：** 一条信息该不该出现在文档、截图、对话里，先按这四条过一遍。

1. 真实密钥一律写成 `<MAGPIE_KEY>` 这类占位符，真实值只放 `.env`；部分打码也不行。
2. 不出现内网主机名、真实管理 IP、真实设备编号。
3. 不把现网导出的数据粘进提示词；要用先做格式保留脱敏。
4. 日志里的敏感字段在写盘前脱敏，不是事后删。

**判断依据：** "贴上去之后再删"从来删不干净——截图、缓存、提交历史都会留。

## 0-5 时间盒与三个必停点

**一句话：** 下面三个点你必须停手问人，因为**这不是你一个人能决定的事**。

| 必停点 | 为什么必须停 | 典型例子 |
|---|---|---|
| **规格没写到的地方** | 你不知道该不该做，猜了就错 | 规格写"支持改价"，没说立即生效还是走审批 |
| **要装新的依赖或工具** | 影响别人的环境和部署 | 为省事引入一个新库 |
| **要改已冻结的接口或契约** | 下游已按老样子写了 | 改订单号格式 |

**三篇的时间盒：** 第一篇 A 50 分钟、B 25–40 分钟、C 全程约 4–5 小时（单环不超过 1 小时，第 3 环可用满 1 小时）；第二篇课堂约 120 分钟；第三篇按附录 8 作战图。

**停下时怎么汇报（三句话）：** 这一部分做完了什么 → 卡在哪一条 → 需要谁拍什么板。需要拍板时列 2–3 个选项与各自代价。

## 0-6 两条贯穿全篇的硬纪律

1. **展品一行不改**：演示页 `index.html` 与四幕记录是展品，**不许改**。要改就改生成它的记录，再重新生成。
2. **三处未达标原样保留**：第二篇的三处未达标（场景一不可判定、场景二 EX 未达标、场景三 P/R 成对）**不许改写成"达标"**，也不许"基本达标""阶段性达成"。

这两条不是文风要求，是诚信底线——退一次，后面所有数字都不再有人信。
