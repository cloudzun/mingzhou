## 0-1 gstack 是什么

**一句话：** gstack 是 Garry Tan 开源的 AI 开发工作流框架，它的核心不是代码，是**八环顺序**——先逼问需求（`/office-hours`）、再锁规格（`/spec`）、再会审（`/autoplan`）、然后才允许写代码（受控施工）、再审查（`/review`）、实机验收（`/qa`）、发布（`/ship`）、量化复盘（`/retro`）。

**为什么顺序不能跳：** 跳过第 1–3 环直接写代码，后面每一环都会退化成"给已经写好的东西补文档"。这是我们观察四幕迭代时最想让你看见的一件事——R1 到 R3.5 加了那么多功能，八环的**定义**一次没变，变的只是每环的投入。

| 你可能听过 | 实际情况 |
|---|---|
| "gstack 是个代码生成工具" | 不是。它不生成代码，它约束你和智能体的协作顺序 |
| "装好就自动变强" | 不会。它提供的是技能与门禁，判断仍然由人做 |
| "八个环 = 八个命令" | 只有 7 个环有斜杠命令；**第 4 环"受控施工"没有命令**，是照规格手写加护栏 |

## 0-2 装 gstack：三步，与宿主无关

**要点先说：gstack 不绑定某一种编码智能体。** 它是一包技能（skills）+ 一套工作流约定，装到哪个宿主里由你定。所以本节给三步通用法，另给一张宿主适配表。

### 步骤 1：装

```bash
git clone https://github.com/garrytan/gstack.git ~/gstack
cd ~/gstack && ./setup --host <你的宿主>
```

`--host` 填你实际用的编码智能体标识。**取值以 `./setup --help` 打印的列表为准**，不要照抄别人的。

国内网络拉不动 GitHub 时，用镜像前缀：

```bash
git clone https://ghfast.top/https://github.com/garrytan/gstack.git ~/gstack
```

### 步骤 2：验证（必须做，别跳过）

在宿主的对话里输入 `/office-hours`：

- 能触发技能、并开始追问你的项目背景 → 装好了；
- 提示"未知命令" → 宿主没加载到技能，回步骤 1 换 `--host` 重装。

也可以直接看技能目录是否落下：

| 宿主类型 | 技能落点（以 opencode 已验证的路径为例） |
|---|---|
| CLI 型（如 opencode） | `~/.config/opencode/skills/` 下出现 `office-hours`、`spec`、`autoplan`、`review`、`qa`、`ship`、`retro` 等目录 |
| 其他宿主 | 目录名随宿主不同，**以 `./setup --host <宿主>` 的输出为准**，不要凭记忆填 |

### 步骤 3：宿主适配表（三类，任选其一）

| 类型 | 典型宿主 | 八环怎么用 | 注意 |
|---|---|---|---|
| **A 有 skills 机制的 CLI** | opencode、codex、claude-code 等 | 走上面的 `./setup --host <宿主>`，八环变成斜杠命令 | 最省事，推荐课堂用这类 |
| **B IDE 插件型** | 各类 IDE 内置智能体 | 插件通常没有 skills 目录 → 用**手动注入**：把 gstack 仓库里对应技能的 `SKILL.md` 作为对话前置贴给它 | 每开新会话要重贴一次 |
| **C 纯对话型（网页版）** | 任意网页智能体 | 走**驱动指令兜底**（见下） | 八环靠纪律约束，不靠命令 |

**C 类兜底写法（不装也能走完八环）：**

```text
按 gstack 八环依次推进，顺序不可跳过、不可打乱：
第 1 环 office-hours → 第 2 环 spec → 第 3 环 autoplan → 第 4 环 受控施工
→ 第 5 环 review → 第 6 环 qa → 第 7 环 ship → 第 8 环 retro。

每一环结束停下汇报：这一环做了什么、交了哪些文件、门禁结果是什么。
需要我拍板的地方，列 2 到 3 个选项和各自代价，等我选。
```

> **本手册的立场：不指定编码智能体型号。** 你用什么工具都行，判据只有一条——**八环的产物有没有落盘**。用了高级工具但产物不落盘，等于没做；用网页版但每环都交了文件，照样算过关。

### 步骤 4：装不上怎么办

| 现象 | 原因 | 处理 |
|---|---|---|
| `git clone` 卡住或 443 超时 | 国内网络 | 用 `ghfast.top` 镜像前缀；或让讲师发离线包 |
| `./setup` 提示不认识的 host | 宿主标识写错 | `./setup --help` 看列表；没有你的宿主就走 C 类兜底 |
| 装完仍"未知命令" | 装到了另一个宿主的目录 | 删掉 `~/gstack` 重装，`--host` 与你当前使用的宿主一致 |
| 技能能触发但不按顺序走 | 缺流程纪律 | 补贴 C 类兜底那段；或检查是否有"禁止全自动执行"的约束 |
| Windows 下 `./setup` 不可执行 | 缺执行位或无 bash | 用 Git Bash 跑；仍不行直接走 C 类兜底 |

## 0-3 证据四态：写"验过了"之前先交代有多硬

**一句话：** 这四个词的作用只有一个——**防止"没验的事被写成验过了"**。

| 你实际的情况 | 报告里该写 | 最常见的错法 |
|---|---|---|
| 真跑过、有输出 | 正常写结论 + 附证据文件 | — |
| **只有真人能验**（好不好用、无障碍、真实用户） | `UNVERIFIED`（未验证） | 写成"通过" |
| **想验但工具或端点用不了** | `unavailable`（不可用） | 编一个分数 |
| **只验了一部分** | `partial`（部分覆盖） | 写成"全覆盖" |
| **本地验不了，得部署到远端或别人配合** | `requires-remote`（需远端验证） | 写成"本地已验证" |

**真实例子：** R1 健康分 98、R2 是 94、R3 是 95——**一个都不等于通过**。以 R2 为例：健康分 94，可这个数字不能单独看，它旁边还写着几行：无 Critical/High，2 个 Medium 与 2 个 Low 未修，人工验收只做了一部分，无障碍相关项 `UNVERIFIED`。分数旁边缺这句，就会被读成"通过"。

**铁律：未验证不等于已验证为否。** 工具没报问题，可能只是它没覆盖到——不能写成"没有问题"。

## 0-4 脱敏与密钥纪律

**一句话：** 一条信息该不该出现在文档、截图、对话里，先按这四条过一遍。

1. 真实密钥一律写成 `<MAGPIE_KEY>` 这类占位符，真实值只放 `.env`；部分打码也不行。
2. 不出现内网主机名、真实管理 IP、真实设备编号。
3. 不把现网导出的数据粘进提示词；要用先做格式保留脱敏。
4. 日志里的敏感字段在写盘前脱敏，不是事后删。

**判断依据：** "贴上去之后再删"从来删不干净——截图、缓存、提交历史都会留。

## 0-5 时间盒与三个必停点

**一句话：** 下面三个点你必须停手问人，因为**这不是你一个人能决定的事**。

| 必停点 | 为什么必须停 | 典型例子 |
|---|---|---|
| **规格没写到的地方** | 你不知道该不该做，猜了就错 | 规格写"支持改价"，没说立即生效还是走审批 |
| **要装新的依赖或工具** | 影响别人的环境和部署 | 为省事引入一个新库 |
| **要改已冻结的接口或契约** | 下游已按老样子写了 | 改订单号格式 |

**三篇的时间盒：** 第一篇 A 50 分钟、B 25–40 分钟、C 全程约 4–5 小时（单环不超过 1 小时，第 3 环可用满 1 小时）；第二篇课堂约 120 分钟；第三篇按附录 8 作战图。

**停下时怎么汇报（三句话）：** 这一部分做完了什么 → 卡在哪一条 → 需要谁拍什么板。需要拍板时列 2–3 个选项与各自代价。

## 0-6 两条贯穿全篇的硬纪律

1. **展品一行不改**：演示页 `index.html` 与四幕记录是展品，**不许改**。要改就改生成它的记录，再重新生成。
2. **三处未达标原样保留**：第二篇的三处未达标（场景一不可判定、场景二 EX 未达标、场景三 P/R 成对）**不许改写成"达标"**，也不许"基本达标""阶段性达成"。

这两条不是文风要求，是诚信底线——退一次，后面所有数字都不再有人信。
